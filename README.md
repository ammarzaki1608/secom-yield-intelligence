# SECOM Yield Intelligence

A DMAIC-structured quality analytics project on the SECOM semiconductor manufacturing dataset — applying Statistical Process Control, process capability analysis, and root-cause-informed feature engineering before training a failure-prediction model, rather than treating this as a plain classification exercise.

**Status: Phase 3 complete, Phase 4 next.**

## Why this project

Most public SECOM notebooks jump straight to "load data → train XGBoost → report accuracy." This project is structured the way a real quality investigation would run: monitor for instability (SPC), quantify whether the process meets requirements (Cp/Cpk), narrow down likely causes before modeling (root cause analysis), then predict and explain (XGBoost + SHAP) — closing the loop back to the causes.

## Dataset

[SECOM](https://archive.ics.uci.edu/dataset/179/secom) — 590 anonymized sensor/process features across 1,567 production entities, ~6.6% failure rate, timestamped per run.

**Note:** SECOM ships without official engineering spec limits. Where spec-limit-dependent analysis (Cp/Cpk) is needed, this project derives proxy limits from historical in-control distributions — a documented, stated assumption, not a claim of real fab specs.

**Getting the data:** raw files are gitignored (not included in this repo). Download `secom.data` and `secom_labels.data` from the link above and place both in `data/raw/`.

## Project structure
```
data/raw/        # raw SECOM files (gitignored, see above)
data/processed/  # cleaned data output (empty for now)
docs/            # problem statement and learning log
notebooks/       # numbered phases, run in order
src/secom/       # reusable package: loading, time split, leakage-safe cleaning, SPC charts
tests/           # pytest tests for src/secom
reports/figures/ # exported charts (empty for now)
```

## How this project was built

The first version of this project (data loader, cleaning code and an SPC
notebook) was generated by AI, and I copied it without really understanding it.
I have since started over. I am rebuilding the project one step at a time with
Claude acting as a tutor: it explains each concept and sets exercises, and I
write and run most of the code myself, then explain it back.

Claude's direct contributions in the rebuild: the final version of
`src/secom/data.py`, skeletons with blanks for `src/secom/cleaning.py`, parts of
the tests, the final layout and text of notebook 02, 03, the Phase 2, Phase 3 entry in the learning log, and edits to other documentation. 

**Done so far:**
- Loading the raw SECOM files, joining sensors to labels and sorting by time
- Chronological train/test split, with the test period kept locked
- Leakage-safe cleaning: drop rules and medians learned from the training period only
- SPC control charts on the training period, with one refit where outliers distorted a baseline

**Not yet done:** process capability (Cp/Cpk), root-cause analysis, modelling. Notebook 01
is an early baseline whose cleaning rules use all rows, so they leak; notebook 02 replaces it.
